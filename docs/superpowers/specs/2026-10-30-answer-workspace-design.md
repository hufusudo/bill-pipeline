# 回答页 A 与复杂账单问答改进

日期：2026-10-30。状态：设计规格，待用户审阅。

## 目的与已选方向

用户已选择 A「账单研究室」，并同意改善复杂问答能力。保留现有 NiceGUI、SQLite 和模型配置，落地“左侧结论、右侧依据”的回答页，使用户能连续追问、看见查询进度，并在预算耗尽时得到诚实的阶段性回答。

设计基准：`.superpowers/brainstorm/13374-1793323685/content/answer-directions.html` 的 A 方案。该稿里的所有金额为虚构示例，产品不得硬编码示例结论、指标或图表。

## 当前问题

- `assistant.py` 的 5 次模型调用同时承担查数和回答，第 5 次取数后直接放弃。
- 每次 `ask()` 重新构建 messages，页面也清空前答，无法承接追问。
- 六个只读工具以单月为主，没有日期范围聚合和跨月分类变化计算。
- 页面只在整个调用结束后显示答案，依据仅显示工具名，没有查询结果和覆盖范围。

## 1. 回答页

桌面端主区与依据栏约为 7:3，窄屏单列且依据折叠。沿用现有导航、绿色强调色和字体，不重做其他页面。

未提问时显示标题、所选月份、三个可点击问题示例及输入区。问题示例仅填入输入框，不自动发送。

回答后保留当前页面会话中的问答；默认聚焦最新回答，允许查看此前问答。左侧按“问题、查询状态、回答、继续追问”排列。右侧展示当前回答的依据：查询名称、条件、覆盖时间、全量合计、返回明细数和是否截断；具体明细可展开。右侧跟随用户选中的回答。

回答优先使用 Markdown 结论、列表和表格；有可验证结构化结果时，再显示确定性生成的对比指标与图表。不得从模型自由文本猜取金额来画图。无合适结果时只显示回答和依据。

输入区提供“快速问答 / 深度分析”，默认为快速；执行时禁用重复提交并显示停止按钮、已完成查询数和当前查询名称。这里呈现查数活动，不展示模型内部思考。保留“这次查了什么”入口。未配置模型、空数据库、查不到数据和接口失败分别给出可操作提示。

## 2. 查询预算与最终回答

快速模式允许最多 5 批工具查询；深度模式允许最多 15 批。每批是一次模型回复中的工具调用集合，每批最多执行 6 个工具；多余调用也必须获得“超过本批上限”的对应工具回复以保持消息协议完整，不静默丢弃。

若模型自行给出答案，立即结束。预算耗尽时，额外保留至多一次禁止调用工具的总结请求，要求仅基于现有结果回答、明确未完成部分。最终总结仍返回工具请求或为空时，用程序生成的阶段性说明收尾，不再取数。没有成功取数时明确说明缺乏数据依据，不生成金额结论。

同一轮内重复的工具与规范化参数共用已有结果；对跨轮重复查询复用本题缓存。连续两批没有新增成功查询时提前进入总结，避免模型循环。错误参数返回可修正提示，不把错误当有效证据。缓存只作用于单次提问，防止后续数据变更导致旧结果复用。

查询阶段时间预算：快速 60 秒、深度 180 秒；总结阶段另限 30 秒。每次模型请求超时不超过 30 秒和本阶段剩余时间的较小值，本题关闭 SDK 自动重试，避免重试越过预算。计时用单调时钟；不可把这些数字承诺为精确完成时长。

停止采用协作取消：发出停止信号后，不再开始新查询或新模型请求，保留已有结果并立即展示“已停止”的阶段性状态；已经发出的网络请求可能等到超时才退出。取消不触发额外付费总结请求；其迟到结果不得覆盖界面或进入后续会话。每次运行有独立标识，切页/清空会话后旧运行也不能回写新视图。

## 3. 连续追问与会话

会话存于当前页面的 Context 内存中，刷新或关闭页面后清除，不新增数据库表或云端同步。切换应用内面板保留会话。提供“新对话”清空入口；运行中先停止再清空。

向模型传入最多最近 6 组已完成问答，加当前问题。历史仅含原用户问题、最终回答和有上限的结构化依据摘要，不重放无限增长的明细或旧工具协议。单条历史问题/回答上限分别为 2,000/6,000 字符，单组依据摘要上限 4,000 字符；超长显式标记截断。为兼容思考模型，本题内部仍完整保留 SDK 返回的 assistant 消息及必要字段。

每组历史记录当时的默认月份；当前页面选择的月份作为本题默认值，不悄悄重写历史月份。切换月份时保留问答但显示“默认月份已切换”的提示。提示词区分默认范围与用户明确指定范围，追问存在歧义时先澄清。导入和重新归类后的新问题重新查询，不能只靠历史金额作答。

## 4. 工具改进

保留现有六工具，扩展搜索并增加两个确定性聚合工具，不向模型开放 SQL 或 Python 执行：

- `compare_months(base_month, target_month)`：返回两月消费、收入、净额、分类消费以及按分类对齐的增量、占总增量比例。基期为零时增幅为空并标明原因；总消费无增加时不使用“增长贡献”措辞。金额以整数分计算，展示到分；百分比由程序计算。
- `range_summary(start_date, end_date, group_by)`：日期两端包含在内，支持按日、月、分类汇总消费和收入。日期必须真实、起止有序，最长 366 天。返回实际数据覆盖范围，提示跨月缺数据；不把无账单月份当作确认零消费。组数最多 366。
- `search_transactions`：保留旧参数兼容，增加起止日期和 offset 分页。每页最多 50 条，全量匹配笔数、消费/收入合计不受分页影响；返回 offset、has_more、truncated。月份和日期范围可同时使用，取交集；无效参数返回清晰错误。排序加入稳定唯一键，避免相同时间的交易翻页重复/遗漏。

统一校验 limit 为 1—50 的整数，offset 为非负整数，拒绝布尔值、负数和非整数。所有新工具沿用现有消费计入口径、参数化查询和个人交易脱敏规则。对个人隐藏商品文本，不增加导出、写账单或联网查询能力。

## 5. 模块与数据流

`db.py` 负责筛选/聚合，`assistant.py` 负责工具协议和有界循环；单独会话/运行状态模块负责预算、取消事件和进度事件类型；问答 UI 提取到 `web/ask.py`，`pages.py` 保留路由和上下文接入，`theme.py` 添加局部样式。只有在依赖关系需要时拆辅助模块，不进行无关重构。

UI 收集问题、模式、默认月份与历史快照 → 工作线程建立独立数据库连接 → 循环通过线程安全队列发布开始/查询/结果/完成事件 → 主事件循环消费队列更新界面。工作线程不直接调用 NiceGUI UI，不跨线程使用 SQLite 连接。界面按运行标识接收事件，连接在 finally 中关闭。

结果模型包含回答文本、查询依据、完成状态、停止原因、所用查询批数和耗时。状态至少区分完整回答、预算结束后的部分回答、取消、超时和接口失败。用户文案不暴露密钥、配置值或原始接口异常。

## 6. 验收与验证

使用临时数据库、虚构账单和 FakeLLM 完成自动验证，不自动调用真实付费模型。

1. 第 5 批查到数据后仍能最终总结；深度模式可完成超过 5 批的不同查询。
2. 单轮多工具、重复查询、无进展、错误参数和强制总结不服从时都在预算内终止。
3. 用可控时钟验证超时边界；停止后不再发起请求且迟到响应不更新 UI。
4. 跨月类别增量、零基期、日期范围边界、缺账单提示、分页全量合计与稳定排序结果正确。
5. 新工具与追问上下文继续保护个人交易字段；接口异常不泄露 key。
6. 连续追问保留上下文；新对话清空；切页返回保留；切换月份显示范围变化。
7. 浏览器核查 A 布局在桌面与窄屏下的空态、执行态、正常回答、部分回答和错误态；数字指标均能追溯到结构化依据。
8. 运行受影响单元/UI测试后运行现有测试全集，检查其他账单页未被破坏。

## 范围边界

本次不更换模型提供商、不修改 .env、不安装系统包、不改系统配置、不增加账户连接或后台主动分析。不保证所有复杂问题都能答出；以更多可用查询能力、正确的结束行为和可核验结果作为验收标准。

## 方案取舍

仅提高轮数成本最低但无法修复追问与查询能力，故不采用；无限循环缺少结束边界，故不采用。采用现有只读工具体系上的有界循环、确定性组合查询与会话上下文，保持实现范围与现有项目一致。

## 自检

已明确预算含义、最终调用、取消与网络超时边界、上下文上限、金额计算、日期范围与缺数据语义；无占位项。后续实现计划按数据工具、运行循环、问答 UI、整体验收的顺序安排，并为共享文件指定唯一修改者。
